# Scaffold `EHL-Cognition` — Robot CI (Devin autonomous layer for robotics)

## Context

This repo is the entry for the **Cognition track at the TUM.ai / EHL hackathon**. The track brief (keynote slide 18) is *"Devin for X — Building the Autonomous Layer"*: pick a domain whose output can be expressed as code, then build a system that **programmatically triggers Devin sessions via the API**, gives them a way to **check their own work**, and produces **real artifacts with no human in the loop**.

The chosen domain is **robotics**. The thesis: robotics already has the feedback loop software has — it's called simulation — but nobody has wired an autonomous engineer into it. Robotics teams therefore have no CI: they push code that drives real hardware, test it once by hand, and discover regressions weeks later on a physical robot.

**What we're building.** A developer pushes control code for a real robot (e.g. a robot arm) to their repo. Our system wakes up, has Devin stand up a simulation of that exact robot — resolving or generating its physical model — runs the pushed code across a large matrix of randomized simulated worlds, and for every failure dispatches a fleet of Devin sessions that reproduce it, find the root cause, fix it, and prove the fix by re-running the full suite. It ends with a written incident report and a pull request containing working code and video evidence. A React dashboard shows the whole thing live: which agents exist, what each is working on, and how they communicate — like watching a software engineering team.

**This task is scaffolding only.** Produce the complete folder structure, config files, and stub modules with docstrings and `TODO`s. Do not implement pipeline logic, simulation, or Devin calls yet — a later session will direct that build. The written docs (`README.md`, `docs/`) are the exception: they must be real content, because they become the spec that later agent sessions implement from.

### Pipeline stages (encode as an enum in `packages/orchestrator/pipeline.py`)

`TRIGGERED → RESOLVE_MODEL → BUILD_HARNESS → DESIGN_SCENARIOS → RUN_SUITE → CLUSTER_FAILURES → INVESTIGATE (fan-out) → FIX (fan-out) → VERIFY → REPORT → PR_OPENED`

Terminal states: `PASSED_CLEAN`, `PR_OPENED`, `FAILED_UNRESOLVED`.

### Agent communication model (document in `docs/AGENT_ROLES.md`)

Devin sessions cannot talk to each other directly. The orchestrator **mediates**: every agent writes findings to `blackboard.py`, and the orchestrator relays relevant findings into other sessions' prompts. Each relay is emitted as a typed message on `bus.py`, which is what `TeamChat.tsx` and `AgentGraph.tsx` render.

Message shape: `{ id, run_id, from_role, to_role | "broadcast", kind: hypothesis|finding|question|answer|verdict|handoff, body, refs[], ts }`.

This is the honest architecture *and* the best part of the demo — say so in the docs.
